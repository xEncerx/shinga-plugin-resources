# Создание плагина Shinga — v1

[Манифест](manifest.md) · [Справочник Dart-скрипта](script.md)

Плагин-источник состоит из манифеста и одного Dart-скрипта. Манифест объявляет идентификатор, настройки и сетевые домены; скрипт реализует поиск, метаданные тайтлов и, при поддержке источником, содержимое главной страницы и ссылки для чтения.

## 1. Создайте манифест

Следуйте [справочнику манифеста](manifest.md). Укажите `manifestVersion: 1`, `pluginApiVersion: 1`, стабильный `id` в формате reverse-DNS, версию выпуска `version` по SemVer и `entry`, указывающий на Dart-файл. Объявляйте только необходимые сетевые хосты и настройки.

Исполняемый исходник состоит из двух файлов:

```text
manifest.json
index.dart
```

`index.dart` — лишь пример имени точки входа, а не фиксированное требование; допускается безопасный вложенный путь. Не помещайте учётные данные ни в один из файлов. Сетевые объявления только запрашивают доступ; разрешения по-прежнему должны быть одобрены пользователем.

## 2. Напишите скрипт

Следуйте [справочнику Dart-скрипта](script.md), начав со [структуры скрипта](script.md#структура-скрипта) и [полного примера](script.md#полный-пример-скрипта).

Реализуйте три обязательных метода:

- `getSearchSchema` — локальные поля поиска и сортировки либо пустая схема.
- `search` — одна страница превью тайтлов и необязательное состояние пагинации.
- `getTitle` — полные метаданные по стабильному локальному ID тайтла источника.

Реализуйте `getHome` и `getInitialReadUrl`, только если источник поддерживает эти операции. Используйте унаследованный `context` для настроек, постоянного хранилища, HTTP, логов и информации о среде выполнения. Поля провайдера не сохраняются между вызовами.

## 3. Проверьте исходник

Перед подписанием итоговых файлов проверьте, что:

- Манифест и скрипт проходят проверку API v1.
- Поиск только по запросу работает без локальных defaults; объявленные фильтры, исключения и сортировки действительно применяются.
- Пагинация продолжает тот же запрос и завершается с `nextContinuation: null`.
- ID из поиска и главной страницы разрешаются через `getTitle`; отсутствующие метаданные не подменяются выдуманными.
- Отсутствующие тайтлы, ограничение частоты, недоступность источника и неподдерживаемые операции используют соответствующие [ошибки](script.md#ошибки), а не пустые успешные ответы.
- Необязательные настройки и отсутствие разрешения на сеть обрабатываются явно; секреты не попадают в логи.
- Результаты, кэшированные значения и HTTP-запросы не превышают [лимиты](script.md#ограничения).

Прохождение проверки не заменяет запуск и проверку методов на фактических ответах сайта. Это руководство описывает контракт плагина, а не элементы редактора или интерфейс тестирования.

## Подпись

Сейчас подпись выполняется отдельным tooling-скриптом; это не код для ограниченного entry-файла плагина. Запускайте такой скрипт в Dart-окружении, где доступны пакеты `plugin_runtime` и `plugin_protocol`. Импортировать эти API в сам скрипт плагина нельзя.

1. Создайте пару Ed25519 один раз через `await PluginSigningService().generateKeyPair()`. Надёжно храните `.privateKeySeed` как исходные данные длиной 32 байта вне пакета плагина и системы контроля версий. Сервис не сохраняет ключ за вас.
2. Используйте этот seed для последующих выпусков. Публичный ключ определяет подписанта; изменение `id` или имени плагина не подтверждает личность издателя, а создание нового ключа меняет идентичность подписанта.
3. Подпишите окончательные точные байты манифеста и entry-файла. Вызов `.toBytes()` сериализует результат в metadata для `signature.json`.

Например, сохраните отдельный tooling-скрипт как `sign.dart`:

```dart
import 'dart:convert';
import 'dart:io';
import 'package:plugin_protocol/plugin_protocol.dart';
import 'package:plugin_runtime/plugin_runtime.dart';

Future<void> main(List<String> args) async {
  if (args.length != 3) {
    throw ArgumentError('Usage: sign.dart <source-dir> <seed-file> <signature-file>');
  }
  final root = Directory(args[0]).absolute.uri;
  final manifestBytes = await File.fromUri(root.resolve('manifest.json')).readAsBytes();
  final parsed = PluginManifestParser().parse(utf8.decode(manifestBytes));
  if (!parsed.isSuccess) throw const FormatException('Invalid manifest');
  final entryPath = parsed.manifest!.entry.value;
  final entryBytes = await File.fromUri(root.resolve(entryPath)).readAsBytes();
  final seed = await File(args[1]).readAsBytes();
  final signed = await const PluginSigningService().sign(
    privateKeySeed: seed,
    manifestBytes: manifestBytes,
    entryPath: entryPath,
    entryBytes: entryBytes,
  );
  await File(args[2]).writeAsBytes(signed.toBytes());
}
```

Запустите его с уже существующим файлом seed, например:

```sh
dart run sign.dart ./source /secure/publisher.seed ./signature.json
```

Храните tooling, закрытый ключ и результат подписи отдельно от двух исполняемых файлов плагина. Metadata подписи сопровождает подписанный исходник; она не является дополнительным исполняемым файлом и не импортируется скриптом. Signing-сервис создаёт metadata, а не установочный архив; подпись не проверяет соответствие реализации API скрипта.

Любое изменение манифеста, пути entry или байтов скрипта требует новой подписи, включая пробелы и переводы строк. Форматирование или правка после подписи делает её недействительной. Сама metadata подписи и другие файлы разработки не подписываются.

Корректная подпись подтверждает, что покрытые ею байты были подписаны соответствующим ключом. Она **не** делает код безопасным, не утверждает разрешения и не присваивает автоматически статус доверенного издателя. Валидная подпись неизвестного приложению ключа получает статус `unknownSigned`; ключи, распознаваемые приложением, могут получить `trustedPublisher` или `shingaDeveloper`. Отсутствующая metadata — `unsigned`, некорректная или несовпадающая — `invalid`.
