# Dart-скрипт плагина — API v1

[Создание плагина](README.md) · [Манифест](manifest.md)

Плагин-источник преобразует ответы API сайта или текстовые данные в модели Shinga. Напишите один Dart-файл точки входа, используя SDK ниже; Shinga предоставляет `context` и вызывает методы провайдера. Диспетчер, JSON-конверт или `main()` в плагине писать не нужно.

## Структура скрипта

Импортируйте SDK ровно один раз, без префикса, `show` или `hide`:

```dart
import 'package:shinga_plugin_sdk/shinga_plugin_sdk.dart';
```

Объявление провайдера должно иметь следующую форму:

```dart
final class SourceProvider extends SourceProviderBase {
  // Реализуйте обязательные методы, перечисленные ниже.
}
```

Это объявление показывает только форму класса, а не полный плагин. [Полный пример](#полный-пример-скрипта) приведён в конце.

Правила:

- `SourceProvider` — единственное публичное объявление верхнего уровня. Не добавляйте `main()`.
- Используйте неявный конструктор либо один безымянный конструктор без параметров, не являющийся factory.
- Для провайдера нельзя указывать `abstract`, `with` или `implements`. Не переопределяйте `context` или имена, начинающиеся с `$`.
- Поля провайдера и дополнительные вспомогательные методы должны иметь приватные имена с `_` в начале.
- Приватные функции, классы, enum и именованные extensions верхнего уровня можно использовать как helpers. Не объявляйте переменные верхнего уровня, даже приватные `const` или `final`. Размещайте константы в приватных полях класса.
- Не наследуйте модели SDK и не реализуйте их интерфейсы: они закрыты для такого расширения. Создавайте предоставленные варианты моделей.
- Весь код плагина должен находиться в файле точки входа. Локальные импорты, дополнительные пакеты, `part`, `export`, `library`, deferred- и conditional-импорты не поддерживаются.

Другие разрешённые импорты: `dart:async`, `dart:collection`, `dart:convert` и `dart:math`. Для них допускаются префиксы и import combinators. Нет доступа к `dart:io`, Flutter, файловой системе, сокетам, WebView или базе данных напрямую. Используйте `context.http` и `context.storage`. Встроенного HTML DOM-парсера нет.

Путь точки входа должен оканчиваться на `.dart` в нижнем регистре. Сохраняйте файл в UTF-8 без BOM и NUL-символов. Размер исходника и лимиты исполнения указаны в разделе [ограничений](#ограничения).

### Жизненный цикл вызова

Для каждого вызова создаётся новый провайдер и вызывается один его метод. Поля, статические кэши и побочные эффекты конструктора не сохраняются между вызовами. Хуков инициализации и завершения нет; перед `search()` метод `getSearchSchema()` автоматически не вызывается.

Для сохранения данных между вызовами используйте storage, для состояния пагинации — continuation. Дожидайтесь (`await`) асинхронной работы, необходимой для результата; фоновая работа не гарантированно завершится после возврата метода. Методы должны иметь точные типы `Future<...>` из контракта; `async` необязателен, генераторы не поддерживаются.

Скрипт работает в ограниченном интерпретаторе, а не в полноценной среде Dart VM. Разрешённые импорты не означают доступность любых пакетов или всех возможностей Dart VM.

## Методы провайдера

Используйте явно указанные типы без префиксов импортов и в точности приведённые ниже позиционные параметры. Не объявляйте методы контракта как `static`, generic, nullable, getter или setter.

| Сигнатура | Обязательный | Контракт |
| --- | --- | --- |
| `Future<SourceSearchSchema> getSearchSchema()` | Да | Верните упорядоченные локальные поля поиска и допустимые сортировки. Для поиска только по запросу разрешена пустая схема. |
| `Future<SourceSearchResult> search(SourceSearchRequest request)` | Да | Верните одну страницу превью по явному запросу, выбранным значениям, сортировке и continuation. |
| `Future<SourceTitleDetails> getTitle(SourceTitleId id)` | Да | Загрузите полные метаданные по стабильному локальному ID тайтла источника. |
| `Future<SourceHome> getHome()` | Нет | Верните упорядоченные секции главной страницы. |
| `Future<Uri> getInitialReadUrl(SourceTitleId id)` | Нет | Верните абсолютный HTTP(S) URL, с которого начинается чтение. Это не метод получения списка глав или изображений страниц. |

Не объявляйте необязательный метод, если операция не поддерживается: унаследованная реализация бросает `SourceUnsupportedException`. Все успешные результаты non-null. Пустой результат не заменяет неподдерживаемую операцию или ошибку запроса.

## Идентификаторы и локализованный текст

### Идентификаторы

`SourceTitleId(String value)` содержит стабильный ID сайта, например slug или числовой ID в виде строки. Получайте значение через `.value`; это не обязательно URL. Используйте один и тот же ID в поиске, главной странице и деталях. При вставке в сегмент URL кодируйте его через `Uri.encodeComponent`.

ID не должен быть пустым или состоять из пробелов; автоматической обрезки или нормализации нет. Сравнивайте ID по `id.value`, а не по идентичности объектов-обёрток.

| ID | Должен быть уникален в пределах |
| --- | --- |
| ID тайтла | Одной страницы поиска или одной секции главной страницы; один тайтл может встречаться в разных секциях. |
| ID секции поиска | Схемы. |
| ID поля поиска | Всей схемы, включая все секции. |
| ID варианта выбора | Своего поля. |
| ID сортировки | Схемы. |
| ID секции главной страницы | Результата главной страницы. |

Кроме `SourceTitleId`, эти ID — обычные строки. ID вариантов принадлежат источнику: это не подписи и не параметры сайта, которые переводятся автоматически.

### LocalizedText и LocaleTag

```dart
final english = LocaleTag.tryParse('en')!;
final title = LocalizedText({english: 'Example title'});
final displayed = title.resolve(english);
```

- `LocaleTag.tryParse(String)` возвращает `null` для неверного тега. Поддерживается формат `language[-Script][-REGION]`: 2–8 ASCII-букв языка, необязательный четырёхбуквенный script, необязательный регион из двух букв или трёх цифр.
- Теги нормализуются: язык — в нижний регистр, script — в Title Case, буквенный регион — в верхний. Подчёркивания, варианты и расширения не поддерживаются. `.value` содержит нормализованный тег; `.language`, `.script`, `.region` — его составляющие.
- `LocalizedText(Map<LocaleTag, String>)` требует непустую карту строк, каждая из которых не пуста и не состоит только из пробельных символов. Исходный текст сохраняется; `.values` — неизменяемая карта.
- `resolve(locale)` ищет точную локаль, затем language-script, если в запрошенной локали заданы и script, и region, затем язык, `en`, после чего — первую локаль в лексикографически отсортированном списке. Текст автоматически не переводится.

Используйте только переводы, предоставленные источником или самим плагином. Все локали учитываются в [лимитах моделей](#лимиты-моделей), а не только отображаемая.

## Модели тайтла и главной страницы

Параметры конструкторов ниже становятся одноимёнными полями только для чтения. Коллекции моделей — неизменяемые копии, включая вложенные списки альтернативных названий. Создавайте новые модели вместо изменения возвращённых коллекций.

### Обложки и превью

```dart
SourceCover({Uri? originalUrl, Uri? thumbnailUrl});

SourceTitlePreview({
  required SourceTitleId id,
  required LocalizedText title,
  required SourceCover? cover,
  LocalizedText? status,
});
```

Параметр `cover` обязателен, но nullable: если обложки нет, укажите `cover: null`. В `SourceCover` может быть указан любой из URL, оба или ни одного. URL обложек и начального перехода к чтению должны быть абсолютными HTTP(S) URL с хостом. Если сайт возвращает относительные пути, преобразуйте их в абсолютные URL.

`status` — локализованная подпись источника, а не enum приложения.

### Полные сведения о тайтле

```dart
SourceTitleDetails({
  required SourceTitleId id,
  required LocalizedText title,
  required SourceCover? cover,
  LocalizedText? status,
  LocalizedText? type,
  Map<LocaleTag, List<String>> altNames = const {},
  int? chapters,
  int? views,
  int? volumes,
  int? favorites,
  double? rating,
  int? scoredBy,
  DateTime? releasedAt,
  DateTime? endedAt,
  List<LocalizedText> genres = const [],
  List<LocalizedText> categories = const [],
  List<String> authors = const [],
  LocalizedText? description,
});
```

| Поля | Правила |
| --- | --- |
| `status`, `type` | Локализованные подписи самого источника. Не выдумывайте статус или тип, если он неизвестен; оставьте поле отсутствующим. |
| `genres`, `categories` | Упорядоченные локализованные подписи, а не ID поисковых вариантов. Порядок и повторы сохраняются. |
| `altNames` | Названия по локалям; в списке каждой локали должны быть уникальные строки, не пустые и не состоящие только из пробельных символов. |
| `authors` | Упорядоченные уникальные имена-строки, не пустые и не состоящие только из пробельных символов. |
| `chapters`, `views`, `volumes`, `favorites`, `scoredBy` | Неотрицательные безопасные целые числа либо `null`, если значение неизвестно. Ноль — известное значение. |
| `rating` | Конечный `double` либо `null`. API v1 не задаёт шкалу рейтинга и не требует количества оценок. |
| `releasedAt`, `endedAt` | Необязательные даты; при сериализации переводятся в UTC. Указывайте только известные источнику даты. |
| `description` | Необязательный локализованный текст с большим лимитом на локаль, чем у обычных подписей. |

Для краткого ответа достаточно `id`, `title` и `cover: null`. Отсутствие необязательных метаданных не является ошибкой. Не возвращайте необработанную разметку или выдуманные значения, если у источника нет пригодного текста.

### Главная страница

```dart
SourceHome(List<SourceHomeSection> sections);

SourceHomeSection({
  required String id,
  required LocalizedText title,
  required SourceHomeSectionKind kind,
  required SourceHomeSectionLayout layout,
  required List<SourceTitlePreview> items,
});
```

- Типы секций: `recommended`, `latest`, `popular`, `trending`, `custom`. Для специфичной источнику секции используйте `custom`.
- Макеты: `carousel`, `grid`.
- Порядок секций и элементов сохраняется. Пустой результат главной страницы и пустые секции допустимы.
- `SourceHomeSectionKind`, `SourceHomeSectionLayout`, `SourceSortDirection`, `PositiveMatchMode` и `SearchSectionKind` имеют `.id` и `fromId(String)`; для неизвестного ID возвращается `null`.

## Поиск

Схема объявляет поддерживаемые фильтры; запрос содержит явные выбранные значения. Провайдер сам преобразует их в параметры сайта. Shinga не выводит синтаксис поиска сайта из ID полей.

### Схема и поля

```dart
SourceSearchSchema({
  List<SearchSection> sections = const [],
  List<SortDefinition> sorts = const [],
});

SearchSection({
  required String id,
  required LocalizedText label,
  required SearchSectionKind kind,
  List<SearchField> fields = const [],
});
```

Секции и поля упорядочены. `SearchSectionKind.basic` и `.advanced` классифицируют поля, но не определяют виджет. Пустые схемы и секции допустимы. ID полей должны быть уникальными во всех секциях.

Для каждого конкретного поля обязательны `String id` и `LocalizedText label`. Необязательный `defaultValue` должен иметь соответствующий тип значения; по умолчанию он равен `null`.

| Класс поля | Дополнительные параметры конструктора | Тип значения |
| --- | --- | --- |
| `TextField` | `TextValue? defaultValue` | `TextValue` |
| `NumberField` | `num? min`, `num? max`, `bool integerOnly = false`, `NumberValue? defaultValue` | `NumberValue` |
| `BooleanField` | `BooleanValue? defaultValue` | `BooleanValue` |
| `SingleChoiceField` | Обязательный `List<ChoiceOption> options`, `SingleChoiceValue? defaultValue` | `SingleChoiceValue` |
| `MultiChoiceField` | Обязательные `List<ChoiceOption> options`, `PositiveMatchMode defaultPositiveMode`; `List<PositiveMatchMode>? positiveModes`, `bool allowExclusion = false`, `MultiChoiceValue? defaultValue` | `MultiChoiceValue` |
| `RangeField` | `num? min`, `num? max`, `bool integerOnly = false`, `RangeValue? defaultValue` | `RangeValue` |

Все параметры именованные. Вариант выбора создаётся так:

```dart
ChoiceOption({required String id, required LocalizedText label});
```

Правила объявлений:

- Варианты поля выбора должны быть непустым списком с уникальными ID в пределах этого поля. Подписи могут повторяться.
- Обе числовые границы необязательны и задаются независимо; указанные границы включительны. Если указаны обе, `min <= max`. Числа конечные; целые должны помещаться в диапазон безопасных целых. `integerOnly` запрещает дробные границы и выбранные значения без округления.
- Если `positiveModes` не указан, используется `[defaultPositiveMode]`. Явный список должен быть непустым, без повторов и содержать `defaultPositiveMode`. Допустимы `PositiveMatchMode.any` и `.all`.
- Перед использованием отрицательного выбора включите `allowExclusion`. Реализуйте все объявленные исключения и не игнорируйте их.
- Значения по умолчанию должны соответствовать объявлению. У default для нескольких вариантов режим должен совпадать с `defaultPositiveMode`.

**Значения по умолчанию инициализируют локальную форму, но не становятся неявными условиями поиска.** Отсутствующая запись в запросе остаётся неустановленной; поиск только по строке не должен применять defaults полей или сортировки.

Одно и то же объявление поля можно использовать в схеме и для типизированного чтения:

```dart
final year = NumberField(
  id: 'year',
  label: LocalizedText({LocaleTag.tryParse('en')!: 'Release year'}),
  min: 1900,
  integerOnly: true,
);
final schema = SourceSearchSchema(
  sections: [
    SearchSection(
      id: 'main',
      label: LocalizedText({LocaleTag.tryParse('en')!: 'Filters'}),
      kind: SearchSectionKind.basic,
      fields: [year],
    ),
  ],
);
final request = SourceSearchRequest(values: {'year': NumberValue(2020)});
SearchSchemaValidator.validateRequest(schema, request);
final selectedYear = year.read(request)?.value; // 2020; null, если поле не выбрано.
```

Общие объявления храните в приватных полях провайдера или приватном helper-объекте, а не в переменных верхнего уровня.

### Выбранные значения

```dart
const TextValue(String value);
NumberValue(num value);
const BooleanValue(bool value);
SingleChoiceValue(String optionId);
MultiChoiceValue({
  required PositiveMatchMode positiveMode,
  List<String> included = const [],
  List<String> excluded = const [],
});
RangeValue({num? min, num? max});
```

- Отсутствующая запись в карте означает, что поле не выбрано. `BooleanValue(false)`, `NumberValue(0)` и `TextValue('')` — явные значения.
- `TextValue` может содержать пустой текст или только пробельные символы. Это отличается от `SourceSearchRequest.query`: если query задан, он не должен быть пустым или состоять только из пробельных символов.
- `SingleChoiceValue.optionId` должен указывать на вариант этого поля.
- `.included` и `.excluded` в нескольких вариантах выбора содержат уникальные непересекающиеся ID. `any` требует совпадения хотя бы с одним включённым вариантом; `all` — со всеми. Пустой список включённых не добавляет положительное условие. Исключённые варианты запрещают совпадения независимо от режима.
- `RangeValue` требует хотя бы одну границу. Границы включительные; `RangeValue(max: 2020)` не задаёт нижнюю. Не подставляйте границы объявления вместо отсутствующих выбранных границ.

### Проверка и типизированное чтение

```dart
SearchSchemaValidator.validateRequest(schema, request);
SearchSchemaValidator.validateValue(field, value);
```

Оба метода имеют тип `static void`. `validateRequest` проверяет все активные значения и выбранную сортировку относительно переданной схемы. Метод не загружает схему, не разбирает continuation и не применяет defaults.

У каждого конкретного поля есть типизированный `read(SourceSearchRequest request)`, возвращающий значение нужного типа либо `null`. Например, `RangeField.read` возвращает `RangeValue?`. Он проверяет только явное значение данного поля, а не остальные поля и сортировку.

Обрабатывайте неподдерживаемый активный выбор отдельно от некорректного объявления:

```dart
try {
  SearchSchemaValidator.validateRequest(schema, request);
} on SearchSelectionException {
  throw const SourceInvalidRequestException();
}
```

`SearchSelectionException` предоставляет `.reason` и необязательные `.fieldId`, `.optionId`, `.sortId`. Причины: `unknownField`, `wrongType`, `outOfBounds`, `textTooLong`, `unknownOption`, `exclusionDisabled`, `unsupportedPositiveMode`, `unknownSort`, `unsupportedDirection`.

Некорректные объявления, повторяющиеся ID или неверные defaults приводят к `ArgumentError`. Исправьте объявление; не превращайте ошибку программы в ошибку пользовательского запроса.

### Сортировка

```dart
SortDefinition({
  required String id,
  required LocalizedText label,
  required List<SourceSortDirection> directions,
});

SourceSortSelection({
  required String id,
  required SourceSortDirection direction,
});
```

Сортировка поддерживает одно или оба уникальных направления: `SourceSortDirection.ascending` и `.descending`. В запросе нужно явно указать объявленную сортировку и поддерживаемое направление. У схемы нет сортировки или направления по умолчанию. Преобразуйте ID и направление в синтаксис сайта самостоятельно.

### Запросы и пагинация

```dart
SourceSearchRequest({
  String? query,
  Map<String, SearchValue> values = const {},
  SourceSortSelection? sort,
  Object? continuation,
});

SourceSearchResult({
  required List<SourceTitlePreview> items,
  Object? nextContinuation,
});
```

- `query == null` означает отсутствие текстового запроса. Если строка задана, она не должна быть пустой или состоять только из пробельных символов.
- `.values` содержит только явно выбранные значения с ключами-ID полей. Пустая карта и отсутствие сортировки допустимы даже при наличии defaults в схеме.
- `.items` — упорядоченная страница результатов. ID внутри страницы не должны повторяться. Пустая страница допустима.
- `.nextContinuation == null` завершает пагинацию. Любое JSON-значение, отличное от `null`, включая `0`, `false` или `''`, считается состоянием пагинации.
- Shinga не анализирует continuation. Используйте номер страницы, cursor или небольшую карту с состоянием, необходимым для следующего запроса. Проверяйте форму continuation перед использованием.
- Продолжайте тот же запрос, с теми же значениями и сортировкой. Любое изменение начинает новый поток с `continuation: null`.
- Не сохраняйте в continuation секреты или ненужные данные ответа и не переходите вслепую по URL пагинации с удалённого сервера. Предпочитайте собственное представление страницы/cursor и известные API endpoints.

Continuation и значения storage должны быть ограниченными JSON-данными: `null`, строки, boolean, безопасные целые, конечные дробные числа, списки и карты со строковыми ключами. Нельзя передавать `Uri`, `DateTime`, модели SDK, циклические структуры и произвольные Dart-объекты. Continuation копируется в глубокий неизменяемый snapshot.

## Контекст

Унаследованный доступный только для чтения `context` содержит:

| Свойство | Тип | Назначение |
| --- | --- | --- |
| `settings` | `SourceSettings` | Чтение эффективных настроек манифеста для текущего вызова. |
| `storage` | `SourceStorage` | Постоянные пары ключ/значение в области этой установки плагина. |
| `http` | `SourceHttp` | HTTP-запросы с разрешёнными полномочиями. |
| `logger` | `SourceLogger` | Диагностические записи с best-effort доставкой. |
| `runtimeInfo` | `SourceRuntimeInfo` | Платформа, локаль приложения и поддерживаемые возможности. |

Не создавайте, не присоединяйте и не подменяйте контекст; не передавайте его параметром методов провайдера.

### Настройки

```dart
Future<T?> get<T extends Object>(String id);
```

Вызывайте `context.settings.get<T>(id)` с точным типом для [настройки манифеста](manifest.md#настройки):

| Тип манифеста | Тип Dart |
| --- | --- |
| `text`, `secret`, `select` | `String` |
| `boolean` | `bool` |
| `num` | `num`, не `int` и не `double` |
| `multiSelect` | `List<String>` |

```dart
final token = await context.settings.get<String>('apiToken');
```

Возвращается эффективное пользовательское значение или объявленный default. Неустановленная необязательная настройка возвращает `null`; обязательная настройка должна быть доступна до запуска метода. Настройки являются snapshot: изменения во время работающего метода не влияют на текущий вызов. API записи настроек нет.

Список для `multiSelect` неизменяемый. Секреты доступны коду плагина как обычные строки; не записывайте их в лог. Неизвестный ID или неверный запрошенный тип вызывает [ошибку настройки](#ошибки-утилит), даже если значение не установлено.

### Хранилище

```dart
Future<JsonValue> get(String key);
Future<void> set(String key, Object value);
Future<bool> remove(String key);
Future<bool> has(String key);
Future<void> batch(List<StorageOperation> operations);

const factory StorageOperation.set(String key, Object value);
const factory StorageOperation.remove(String key);
```

Это методы `context.storage`. `JsonValue` — JSON-совместимое значение, которое может быть `null`.

- `get` возвращает `null` для отсутствующего ключа. `has` проверяет наличие; `remove` сообщает, существовал ли ключ.
- `set` атомарно заменяет значение. Само значение верхнего уровня не может быть `null`, но `null` внутри JSON допустим. Для удаления ключа используйте `remove`.
- `batch` выполняет операции по порядку — все целиком или ни одной. Повторные ключи допустимы; следующие операции видят результаты предыдущих. Квота storage проверяется по конечному состоянию.
- Отдельные вызовы `get` и `set` не образуют атомарную read-modify-write транзакцию. Перечисления ключей, `clear`, compare-and-set и transaction callback отсутствуют.
- При отмене вызова доставка результата может прекратиться уже после начала commit записи; это не гарантирует откат уже сохранённых данных.

```dart
await context.storage.batch([
  StorageOperation.set('catalog-cache', {
    'savedAt': DateTime.now().toUtc().toIso8601String(),
    'ids': ['title-a', 'title-b'],
  }),
  const StorageOperation.remove('old-cache'),
]);
```

Storage сохраняется между вызовами этой установки в отличие от полей провайдера. Это не защищённое хранилище секретов. Задавайте срок жизни кэша самостоятельно и не сохраняйте учётные данные без необходимости.

### Логирование

```dart
void debug(String message, [Map<String, JsonValue>? details]);
void info(String message, [Map<String, JsonValue>? details]);
void warn(String message, [Map<String, JsonValue>? details]);
void error(String message, [Map<String, JsonValue>? details]);
```

Используйте `context.logger`, а не `print`: вывод `print` подавляется. `details` должны содержать JSON-совместимые данные.

```dart
context.logger.warn('Title endpoint rate limited', {'status': 429});
```

Логирование работает по best effort: неверные или избыточные записи могут отбрасываться, старые записи вытесняются, после завершения приложения логи не сохраняются. Подтверждения доставки и метода flush нет.

Известные значения секретных настроек маскируются, но это не универсальный поиск секретов. Не записывайте в логи токены, cookies, заголовки авторизации, полные URL с чувствительными query-параметрами или исходные тела ответов. Токены из HTTP или storage могут быть неизвестны механизму маскировки. Используйте шаблоны endpoint и безопасные коды статуса/ошибок.

### Информация о среде выполнения

```dart
final String platform;
final LocaleTag locale;
final Set<String> capabilities;
```

Получайте эти значения через `context.runtimeInfo`. `locale` — эффективная локаль приложения для текущего вызова. `capabilities` — неизменяемое множество поддерживаемых возможностей API: `settings.read`, `storage`, `http`, `logger` и `runtime.info`.

Поддержка возможности не означает, что операция разрешена: `http` не даёт автоматического доступа к любому домену. Нет API для изменения runtime-информации или перечисления одобренных сетевых хостов. `platform` — строка, не публичный enum.

## HTTP

### API запросов

```dart
SourceHttp withDefaults({required Map<String, String> headers});

Future<SourceHttpResponse> request({
  required String method,
  required Uri url,
  required SourceHttpResponseKind responseKind,
  bool followRedirects = true,
  List<SourceHttpField> query = const [],
  Map<String, String> headers = const {},
  SourceHttpBody? body,
  Duration? timeout,
});

const SourceHttpField(String name, String value);
```

Используйте `context.http` или клиент, возвращённый `withDefaults`:

```dart
final client = context.http.withDefaults(headers: {'Accept': 'application/json'});
final response = await client.request(
  method: 'GET',
  url: Uri.parse('https://api.example.com/titles'),
  query: [
    const SourceHttpField('tag', 'action'),
    const SourceHttpField('tag', 'comedy'),
  ],
  responseKind: SourceHttpResponseKind.json,
  timeout: const Duration(seconds: 15),
);
```

Методы должны быть uppercase HTTP-токенами, например `GET`, `POST` или `QUERY`; фиксированного списка только из GET/POST нет. Неверный метод и неположительный timeout отклоняются. Если timeout не указан, отдельный более короткий предел для HTTP не добавляется; действует предел всего вызова. Указанный timeout охватывает запрос вместе с редиректами.

Поля query добавляются после уже имеющегося query URL, сохраняют порядок и повторяющиеся имена. Передавайте не закодированные имена и значения. Заголовки и query копируются до асинхронной отправки.

### Тела запросов и ответы

| Тело запроса | Кодирование | Content-Type по умолчанию, если не задан |
| --- | --- | --- |
| `SourceHttpBody.text(String value)` | UTF-8 | `text/plain; charset=utf-8` |
| `SourceHttpBody.json(Object? value)` | JSON, включая `null` | `application/json; charset=utf-8` |
| `SourceHttpBody.form(List<SourceHttpField> fields)` | URL-encoded упорядоченные поля с повторами имён | `application/x-www-form-urlencoded; charset=utf-8` |

Соответствующие конкретные классы тела: `SourceHttpTextBody`, `SourceHttpJsonBody`, `SourceHttpFormBody`. JSON и form копируются, поэтому последующие изменения коллекций не повлияют на запрос. Тела запроса в виде raw binary, файла, multipart или потока не поддерживаются.

`SourceHttpResponse` предоставляет:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `status` | `int` | HTTP-статус, включая обычные ответы 4xx и 5xx. |
| `finalUrl` | `Uri` | Принятый конечный URL, включая добавленный query и пройденные редиректы. |
| `headers` | `Map<String, List<String>>` | Неизменяемая карта заголовков с именами в нижнем регистре и сохранёнными повторяющимися значениями. |
| `body` | `SourceHttpResponseBody` | Вариант тела определяется только `responseKind`. |

| `responseKind` | Класс тела | `.value` |
| --- | --- | --- |
| `SourceHttpResponseKind.text` | `SourceHttpTextResponse` | Строго декодированная UTF-8 `String`. |
| `SourceHttpResponseKind.json` | `SourceHttpJsonResponse` | Глубоко неизменяемый JSON `Object?`, включая `null`. |
| `SourceHttpResponseKind.bytes` | `SourceHttpBytesResponse` | Неизменяемый `List<int>` после распаковки. |

```dart
final data = (response.body as SourceHttpJsonResponse).value;
```

Перед чтением JSON-карты проверьте `value is Map<Object?, Object?>`. Используйте эту карту напрямую: вызов `.cast()` на неизменяемых HTTP-картах не поддерживается интерпретатором.

`Content-Type` не определяет способ декодирования. Поддерживаются content-encoding identity, gzip и deflate; Brotli и цепочки кодировок не поддерживаются. Текст декодируется как строгий UTF-8, без определения кодировки по содержимому.

**Проверяйте HTTP-статус самостоятельно.** Ответы 404 или 500 сами по себе не вызывают `SourceHttpException`. Однако декодирование происходит до передачи ответа: HTML вместо JSON, неверный JSON или пустое JSON-тело (включая пустой ответ 204) приводят к `http.decode_failed`. Если нужно проверить статус независимо от разбора JSON, запросите текст или байты, проверьте статус и затем декодируйте сами.

Автоматические повторы, кэш ответов, cookie jar, обработка auth challenge, WebSocket и потоковый API отсутствуют.

### URL, разрешения и заголовки

- Запросы требуют абсолютный HTTP(S) URL с хостом, без userinfo и с допустимым портом. Fragment удаляется. Хост должен быть ASCII без конечной точки; для интернационализированных доменов используйте ASCII/Punycode.
- Каждый адрес, включая редиректы, должен одновременно соответствовать хостам, запрошенным в манифесте, и хостам, одобренным для установки. `*.example.com` не включает `example.com`.
- Прямые запросы к непубличным адресам отклоняются; в частности, если DNS вернул запрещённый адрес, запрос запрещён. Настройки device proxy контролируются приложением, а не плагином.
- Приоритет заголовков: глобальные defaults приложения → локальный `withDefaults` → заголовки запроса. Перезапись нечувствительна к регистру. `withDefaults` возвращает новый неизменяемый клиент, не изменяя исходный.
- `Authorization` и `Cookie` разрешены. Из управляющих символов в значении заголовка разрешён только TAB; DEL и символы выше значения байта 255 запрещены.

Запрещённые имена заголовков без учёта регистра:

```text
host, content-length, connection, keep-alive, transfer-encoding,
te, trailer, upgrade, expect, proxy-authorization,
proxy-connection, proxy-authenticate, и все имена proxy-*
```

### Редиректы и cookies

При `followRedirects: true` HTTP автоматически следует редиректам 301, 302, 303, 307 и 308, не превышая [лимит редиректов](#лимиты-http-и-хранилища). Для редиректа нужен ровно один непустой `Location`; относительные адреса поддерживаются.

- 303 меняет любой метод, кроме HEAD, на GET. 301/302 меняют POST на GET. В остальных случаях метод и тело сохраняются.
- При переходе на GET удаляется тело и все заголовки `content-*`.
- При смене схемы, хоста или порта удаляются credentials и большинство пользовательских заголовков. Локальные defaults после удаления повторно не применяются.
- При смене origin могут сохраниться только `accept`, `accept-charset`, `accept-language`, `accept-encoding`, `user-agent`, `content-type`, `content-encoding`, `content-language`, `content-location`, `cache-control`, `pragma`, `if-match`, `if-none-match`, `if-modified-since`, `if-unmodified-since`, `if-range`, `range`, `referer` и `origin`.
- Каждый переход проверяется отдельно. Тела промежуточных ответов также учитываются в проверках декодирования и размера.

При `followRedirects: false` заголовок `Location` не анализируется: возвращаются обычные статус, заголовки и декодированное тело. Ручной переход — отдельный запрос с отдельной проверкой разрешений.

Cookies обрабатываются вручную. Читайте отдельные значения `Set-Cookie` из `response.headers['set-cookie']`, выбирайте cookies, допустимые для нужного адреса, и явно отправляйте заголовок `Cookie`. Хост не хранит cookies и не переносит cookies из ответа в следующие запросы или редиректы. Не пересылайте credentials на посторонний origin.

## Ошибки

### Результаты источника

У всех пяти исключений `const` конструктор без аргументов. Они не содержат сообщений, причин ошибки или полей retry-after.

| Исключение | Значение | Внешний код |
| --- | --- | --- |
| `SourceUnsupportedException()` | Необязательная операция не поддерживается. | `source.unsupported` |
| `SourceNotFoundException()` | Запрошенный ресурс источника отсутствует. | `source.not_found` |
| `SourceInvalidRequestException()` | Запрос корректно сформирован, но содержит неподдерживаемый выбор или семантику. | `source.invalid_request` |
| `SourceTemporarilyUnavailableException()` | Источник временно недоступен. | `source.temporarily_unavailable` |
| `SourceRateLimitedException()` | Источник ограничивает частоту запросов. | `source.rate_limited` |

Сопоставляйте HTTP-статусы с исключениями по смыслу endpoint. Например, 404 для метода деталей может означать отсутствие тайтла, а 404 каталога — проблему интеграции. Не превращайте все ошибки в пустой успешный результат.

### Ошибки утилит

Эти исключения предоставляют безопасный `.code`; не разбирайте текст сообщения.

| Исключение | Коды |
| --- | --- |
| `SourceSettingsException` | `settings.unknown_id`, `settings.invalid_type` |
| `SourceStorageException` | `storage.invalid_key`, `storage.invalid_value`, `storage.quota_exceeded`, `storage.commit_failed`, `capability.denied` |
| `SourceHttpException` | Список ниже. |

Исключения settings/storage принимают код через конструктор; обычно следует перехватывать ошибки, возникшие при работе с `context`, а не создавать эти исключения самостоятельно. `SourceHttpException(String code)` принимает только закрытый набор:

| Код HTTP | Значение |
| --- | --- |
| `http.invalid_request` | Неверный метод, URL, тело, timeout или payload запроса. |
| `http.invalid_headers` | Неверные, запрещённые или превышающие лимит заголовки запроса. |
| `http.denied` | Адрес не разрешён одновременно хостами из манифеста и одобренными хостами. |
| `http.unsafe_address` | Запрещённый прямой сетевой адрес. |
| `http.stopped` | Полномочия или время жизни операции завершены. |
| `http.cancelled` | Запрос отменён. |
| `http.timeout` | Истёк timeout запроса. |
| `http.resource_limit` | Исчерпана ёмкость HTTP-операций. |
| `http.response_too_large` | Превышен предел размера ответа или заголовков. |
| `http.decode_failed` | Неподдерживаемое кодирование, неверный UTF-8/JSON или слишком большая структура JSON. |
| `http.redirect_failed` | Неверный Location или превышен лимит редиректов. |
| `http.transport_failed` | Другая ошибка транспорта без нативных диагностических сведений. |

Сбой транспорта или timeout можно преобразовать во временную недоступность источника. Неверные заголовки, разрешения и превышение размера обычно требуют другой реакции; не скрывайте все HTTP-ошибки общим «источник недоступен» и не добавляйте бесконечные повторы.

### Ошибки автора и терминальные сбои

| Ситуация | Результат |
| --- | --- |
| Неверные данные конструктора, схема, defaults или повторяющиеся ID | Обычно `ArgumentError`: исправьте плагин. Некоторые правила проверяются только при передаче результата наружу. |
| Неперехваченный `SearchSelectionException` | Общая ошибка плагина, а не автоматический `source.invalid_request`. Преобразуйте явно, когда это уместно. |
| Другое неперехваченное исключение метода провайдера | `plugin.exception`; произвольные сведения об исключении не возвращаются как публичный payload. |
| Некорректный или слишком большой вход/результат API | `api.params_invalid` / `api.result_invalid`; вызов завершается ошибкой. |
| Некорректный или слишком большой совокупный вызов хоста | `host_call.payload_invalid`; это не обязательно перехватываемая ошибка capability. |
| Превышено число общих или одновременных вызовов storage/HTTP | `host_call.protocol_invalid`, а не `http.resource_limit`. |
| Лимит шагов интерпретатора | Ошибка исполнения `execution.step_limit`, а не исключение источника, которое должен имитировать плагин. |
| Таймаут интерпретатора / абсолютный срок вызова | `execution.d4rt_timeout` / `invocation.hard_timeout`; вызов продолжить нельзя. |

Используйте узкие обработчики ошибок. При разборе ошибки Dart-библиотеки в интерпретируемом коде надёжнее использовать общий `catch`, а затем проверить `error is FormatException`: интерпретатор может не распознать нативную ошибку `FormatException` в typed catch. Повторно выбрасывайте посторонние ошибки; не трактуйте любую ошибку кода как недоступность источника.

## Ограничения

Пределы включительные. `KiB` означает 1024 байта; строки ограничиваются по UTF-8 байтам, а не по `String.length` в Dart. В сериализованный JSON входят кавычки и экранирование. Индивидуальные пределы не отменяют общие ограничения размера, числа узлов и вложенности.

| ID поиска/секции/поля/варианта/сортировки/секции главной страницы | 128 байт |
| ID тайтла | 1024 байта |
| URL обложки или чтения | 4096 байт |
| Локалей в одном локализованном поле или карте альтернативных названий | 32 |
| Обычная подпись / имя автора / альтернативное название | 4096 байт |
| Описание на одну локаль | 64 КиБ |
| Результаты поиска на страницу | 100 |
| Секции главной страницы / элементы в секции | 32 / 100 |
| Альтернативные названия на локаль / авторы | 64 / 64 |
| Жанры / категории в деталях тайтла | по 1000 каждого типа |
| Секции поиска / поля во всех секциях | 64 / 64 |
| Явно выбранные поля | 64 |
| Варианты выбора в одном поле | 1000 |
| Включённые + исключённые ID в одном выборе | 1000 |
| Query / выбранный текст | 4096 байт |
| Объявления сортировок | 1000 |
| Каждое сериализованное continuation | 16 КиБ |

Проверки конструктора — не полная проверка результата. Модель может успешно создаться, но сериализация всё равно будет отклонена из-за размера текста, общего объёма, вложенности или лимита целых чисел. Держите результаты компактными и используйте пагинацию.

Исходный Dart-файл точки входа ограничен 256 КиБ UTF-8; приложение может задать меньший предел.

### Лимиты HTTP и хранилища

| Значение | Максимум |
| --- | ---: |
| Ключ storage | 128 байт, не пустой |
| Сериализованное значение storage | 32 КиБ |
| Операции в batch storage | 64 |
| Ключи на одну установку | 1024 |
| Байты ключей + закодированных значений на установку | 1 МиБ |
| Общий payload вызова storage/HTTP с framing | 256 КиБ |
| Одновременно выполняющиеся вызовы storage + HTTP на invocation | 16 |
| Всего вызовов storage + HTTP на invocation | 256 |
| Сжатое / распакованное тело HTTP-ответа | по 8 МиБ |
| Заголовки запроса / ответа | по 64 КиБ |
| Узлы JSON HTTP / вложенность контейнеров | 100000 / 32 |
| Автоматически пройденные редиректы | 5 |
| Сообщение лога | 2048 байт |
| Запись лога | 8 КиБ |
| Отправленные записи лога на invocation | 100 |

Payload storage и HTTP также подчиняются общим ограничениям JSON. Обрамляющие структуры занимают часть бюджета вложенности. Batch из 64 значений по 32 КиБ каждое, хотя значения по отдельности допустимы, не поместится в общий лимит вызова. Тела HTTP-запросов ограничены размером payload вызова, а не пределом 8 МиБ для ответа. В бюджет заголовков входят и заголовки приложения — оставляйте запас.

Логи хранятся только в ограниченной памяти: до 256 записей и 1 МиБ на установку, глобальный предел — 8 МиБ. Это лимиты хранения, а не гарантия доставки.

### Лимиты исполнения

Бюджеты задаёт приложение; увеличить их из скрипта или манифеста нельзя. Стандартный бюджет интерпретатора — 100000 шагов и 120 секунд; абсолютный срок вызова — 125 секунд. Приложение может использовать меньшие пределы; настраиваемый предел шагов хостом — 10000000. Явный HTTP timeout может сократить ожидание, но не продлить время invocation.

## Полный пример скрипта

Пример реализует простой адаптер поиска только по запросу для гипотетического API:

- `GET /titles?q=...&page=N` возвращает `{"items":[{"id":"a","name":"Title"}],"hasMore":false}`.
- `GET /titles/{id}` возвращает `{"id":"a","name":"Title"}`; ответ 404 означает отсутствие тайтла.
- ID и названия — строки, не пустые и не состоящие только из пробельных символов; ID превью в одной странице уникальны.

Объявите `api.example.com` в манифесте и укажите путь к этому скрипту в `entry`. Замените endpoints и преобразование ответа согласно реальному API сайта. Пример реализует все обязательные методы; необязательные главная страница и URL чтения остаются неподдерживаемыми.

```dart
import 'package:shinga_plugin_sdk/shinga_plugin_sdk.dart';

final class SourceProvider extends SourceProviderBase {
  final _schema = SourceSearchSchema();

  @override
  Future<SourceSearchSchema> getSearchSchema() async => _schema;

  @override
  Future<SourceSearchResult> search(SourceSearchRequest request) async {
    try {
      SearchSchemaValidator.validateRequest(_schema, request);
    } on SearchSelectionException {
      throw const SourceInvalidRequestException();
    }
    final cursor = request.continuation;
    if (cursor != null && (cursor is! int || cursor < 1)) {
      throw const SourceInvalidRequestException();
    }
    final page = cursor as int? ?? 1;
    final data = await _getJson(
      '/titles',
      query: [
        if (request.query != null) SourceHttpField('q', request.query!),
        SourceHttpField('page', '$page'),
      ],
    );
    final rows = data['items'];
    final more = data['hasMore'];
    if (rows is! List || more is! bool) {
      throw const SourceTemporarilyUnavailableException();
    }
    final items = <SourceTitlePreview>[];
    final ids = <String>{};
    for (final row in rows) {
      final item = _object(row);
      final id = _text(item['id']);
      if (!ids.add(id)) continue;
      items.add(SourceTitlePreview(
        id: SourceTitleId(id),
        title: _label(_text(item['name'])),
        cover: null,
      ));
    }
    return SourceSearchResult(
      items: items,
      nextContinuation: more ? page + 1 : null,
    );
  }

  @override
  Future<SourceTitleDetails> getTitle(SourceTitleId id) async {
    final data = await _getJson(
      '/titles/${Uri.encodeComponent(id.value)}',
      missingTitle: true,
    );
    return SourceTitleDetails(
      id: SourceTitleId(_text(data['id'])),
      title: _label(_text(data['name'])),
      cover: null,
    );
  }

  Future<Map<Object?, Object?>> _getJson(
    String path, {
    List<SourceHttpField> query = const [],
    bool missingTitle = false,
  }) async {
    final response = await context.http.request(
      method: 'GET',
      url: Uri.parse('https://api.example.com$path'),
      responseKind: SourceHttpResponseKind.json,
      query: query,
    );
    if (response.status == 404 && missingTitle) {
      throw const SourceNotFoundException();
    }
    if (response.status == 429) throw const SourceRateLimitedException();
    if (response.status < 200 || response.status >= 300) {
      throw const SourceTemporarilyUnavailableException();
    }
    return _object((response.body as SourceHttpJsonResponse).value);
  }

  Map<Object?, Object?> _object(Object? value) {
    if (value is! Map<Object?, Object?>) {
      throw const SourceTemporarilyUnavailableException();
    }
    return value;
  }

  String _text(Object? value) {
    if (value is! String || value.trim().isEmpty) {
      throw const SourceTemporarilyUnavailableException();
    }
    return value;
  }

  LocalizedText _label(String value) =>
      LocalizedText({LocaleTag.tryParse('en')!: value});
}
```

Предполагается, что ответы с ошибками тоже содержат JSON. Если сайт возвращает HTML или пустое тело при ошибке, используйте описанный выше подход с проверкой статуса до разбора текста/байтов. Сбои транспорта и декодирования намеренно не маскируются под пустые страницы.
